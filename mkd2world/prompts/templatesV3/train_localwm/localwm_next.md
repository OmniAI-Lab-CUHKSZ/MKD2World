# WM_Local

Given the current screenshot and one candidate GUI action, predict the complete visible interface Markdown after that action is executed.

## Input

- `current_screenshot`: screenshot before the action is executed.
- `candidate_action`: one candidate action generated by the GUI Agent.

## Output Format

Output Markdown directly:

[Environment: Web]
...

Rules:
- Markdown must be the complete visible UI state after the action.
- Markdown must start with `[Environment: Web]`.

## Markdown Grammar

Markdown uses the same `0..999` relative coordinate grid as `candidate_action`.
Each UI element uses center-box coordinates:

`[content](type)<cx,cy,w,h>`

Meaning:
- `cx,cy` are the element center point.
- `w,h` are the element width and height.
- All four numbers are integers on the `0..999` grid.

Valid line formats:
- `[text](text)<cx,cy,w,h>`
- `[text](link)<cx,cy,w,h>`
- `[text](button)<cx,cy,w,h>`
- `[visible value or placeholder](input)<cx,cy,w,h>`
- `[icon: semantic description](icon)<cx,cy,w,h>`
- `[img: semantic description](image)<cx,cy,w,h>`
- `[ ] [label](toggle)<cx,cy,w,h>`
- `[x] [label](toggle)<cx,cy,w,h>`
- `[>] [label](select)<cx,cy,w,h>`
- `[v] [label](select)<cx,cy,w,h>`
- `- [Block: description]<cx,cy,w,h>`
- `[Environment: Web]`

Element type definitions:
- `text`: visible non-interactive text.
- `link`: visible text or content that navigates when activated.
- `button`: An element with a visible border and a color that clearly contrasts with the webpage background. Its content is usually text, and it is generally larger than an icon.
- `input`: a visible editable field; use its current value, otherwise its visible placeholder.
- `icon`: A small graphical symbol whose background color usually matches the webpage background. It may optionally have a black outline.
- `image`: A photograph or visual depicting natural scenes, people, or similar content, with boundaries clearly distinguishable from the webpage background.
- `toggle`: Any checkable element, such as a checkbox or radio button.
- `select`: A dropdown or expandable selection control.



### Toggle State

- `[ ]` indicates unchecked, off, or unselected.
- `[x]` indicates checked, on, or selected.
- Clicking a toggle usually switches between `[ ]` and `[x]`.
- When a toggle state changes, keep the same label and coordinates.

### Select State

- `[>]` indicates collapsed or closed.
- `[v]` indicates expanded or open.
- Clicking a closed select usually expands it and displays options nearby.
- Clicking an open select closes it.

### Block

Block description must be one of:
- `Navigation`
- `Sidebar`
- `Footer`
- `Form`
- `Table`
- `Section`

### Concrete Example


[Environment: Web]

- [Block: Navigation]<500,40,960,60>

  - [icon: menu](icon)<950,40,30,30>
- [Block: Sidebar]<110,350,180,520>

## Prediction Rules

The top-to-bottom order of elements in the prediction should roughly match their order in the webpage viewport.
Prioritize correct semantics and element types, then infer reasonable coordinate positions.


For `left_click` / `double_click` / `right_click`:
- Locate the target element based on coordinates.
- Predict visible navigation, pop-ups, menus, forms or selected states after the click.
- right_click may open a context menu.

For `type_text`:
- Write `text` into the currently focused or target input.

For `scroll`:
- Predict visible content changes from signed relative-screen `delta_x` and `delta_y` integers in `[-999,999]`; magnitude `999` is one full screen. Positive `delta_y` scrolls down, negative scrolls up; positive `delta_x` scrolls right, negative scrolls left.

For `key_press` / `hotkey`:
- `ENTER` is often used to submit forms, search, or confirm.
- `ESC` is often used to close pop-ups, menus, or dropdowns.
- `CTRL/CMD+L` often focuses the address bar; `CTRL/CMD+T` often opens a new tab.

For `navigate` / `go_back` / `go_forward` / `refresh`:
- Predict the visible page after browser navigation.

For `select_option`:
- Update the visible value of the select, close the options list, and remove the old expanded options.

For `drag`:
- Predict sorting, slider position or drag-and-drop result caused by dragging.

For `hover` / `move_to`:
- A tooltip, hover menu, or highlighted state may appear.

For `wait`:
- Predict natural changes such as loading completion, asynchronous results, or pop-ups appearing/disappearing.

For `clear`:
- Clear the target input or the currently focused input area.

For `finish` / `fail`:
- Finish and fail do not change the visible interface.
